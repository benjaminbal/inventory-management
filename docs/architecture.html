Data Flow — Request Lifecycle
1
User selects filters in FilterBar
Dropdowns update refs in the useFilters() singleton composable — warehouse, category, status, period. State is shared across all views.
2
View watcher triggers reload
Each view watches the filter refs. On change, it calls getCurrentFilters() which normalizes params (selectedLocation → warehouse, selectedPeriod → month) and passes them to the API layer.
3
api.js builds query string
Axios appends non-"all" filter values as URL query parameters.
GET http://localhost:8001/api/inventory?warehouse=Tokyo&category=Sensors
4
FastAPI endpoint applies filters
apply_filters() chains warehouse → category → status. filter_by_month() handles direct months (2025-01) and quarters (Q1-2025 → Jan, Feb, Mar). Filters run on in-memory Python lists.
5
Pydantic validates & serializes
FastAPI validates the return value against the Pydantic response model, serializes to JSON, and sends the response. Invalid data raises a 422 automatically.
6
Vue renders filtered data
The view assigns the response to a ref. Computed properties (e.g. filteredItems) derive from the ref + local search query. Template re-renders reactively.
Shared State — Composables
useFilters()
  • selectedPeriod — time/quarter
  • selectedLocation — warehouse
  • selectedCategory — product category
  • selectedStatus — order status
  • getCurrentFilters() — normalized API params
  • resetFilters() — reset all to "all"
useAuth()
  • currentUser — computed, locale-aware
  • tasks — 4 mock task items
  • logout() — session clear
  • getInitials(name) — avatar helper
useI18n()
  • t(key, params) — translate with fallback
  • currentLocale — "en" or "ja"
  • currentCurrency — USD / JPY
  • Persisted to localStorage
